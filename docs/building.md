# Building this branch

## Tools

Install [uv](https://docs.astral.sh/uv/getting-started/installation/) and GNU
gettext (`msgfmt`, `xgettext`, `msgmerge`) on PATH. Windows gettext builds are
available from [mlocati](https://mlocati.github.io/articles/gettext-iconv-windows.html).
The build uses Python 3.13; uv can provide it. This is tooling Python and does
not change the Python used by NVDA. Dependency versions and hashes are in `uv.lock`.

## Build and check

From the repository root:

1. `uv sync --locked`
2. `uv run --locked scons pot`
3. `uv run --locked python tools/check_project.py`
4. `uv run --locked scons`
5. If this branch has a `tests` directory: `uv run --locked python -m unittest discover -s tests -v`
6. `uv run --locked python tools/check_project.py --package --write-checksum`

The output is `dist/vocalizer_automotive_driver-<version>.nvda-addon` with a
SHA-256 sidecar. The PowerShell entry point `tools/Build-PublicAddon.ps1`
delegates to the same build and package validator. Both entry points require
uv and gettext. Package names follow the versioned release naming scheme.

`buildVars.py` defines the variant's metadata. The version, supported NVDA
versions and original author credits are preserved. The placeholder project
version in `pyproject.toml` belongs to build tooling, not the add-on.

## Source and generated files

Edit the Markdown manuals in `addon/doc/en`, `pl` and `sk`; HTML is generated.
The root README files remain repository documentation and do not overwrite
the full manuals. Edit PO files rather than compiled MO files.

The manifest templates and `buildVars.py` generate the main manifest.
Localized summaries/descriptions are in the existing PO catalogs and generate
localized manifests automatically. Original translation values were retained.
The POT remains `vocalizer_automotive_driver.pot` in the repository root.

Generated HTML, MO, manifests, copied notices and build outputs are ignored by
Git. The package excludes translation sources, Markdown, Python bytecode,
backup copies of `nuan_platform.dll` and any `vocalizer_license.ini`, including
case variants. Original runtime source and included engine files are packaged
without modification. Personal license files and voice add-ons are not supplied.

`uv run --locked scons -c` cleans generated outputs and retains source manuals.
An existing tracked POT can also be regenerated by running `scons pot` again.

## Legacy engine preparation

The `legacy-2.1.6-2025` source branch did not contain the engine files included
in its published `v2.1.6-nvda2025` package. Its build restores those same four
files from Git blobs already present in a full clone of this repository.
Their SHA-256 values are checked against `buildVars.py`.

These files were verified byte-for-byte against that published legacy package
and the files in `main`. No files are taken from a working directory on another
branch. No user license is retrieved. The generated legacy engine copies are
ignored by Git and are removed by cleaning. The classic and brokered branches
continue using their existing tracked engine files.

Use a full clone that includes the repository's three branches. A shallow clone
may need `git fetch --unshallow origin`; a clone restricted to one branch may
need to fetch `main` as well. A legacy source ZIP without Git objects cannot
restore missing engine files. Existing matching files at the expected paths
are accepted without restoration.

## Template provenance

Build tools are based on [NVDA Add-on Template revision 56f272d5e37711949b9baf069194455f0386f152](https://github.com/nvaccess/AddonTemplate/tree/56f272d5e37711949b9baf069194455f0386f152).
The adaptations keep separate manuals, use `dist`, track native assets and
notices, preserve manuals on clean, compile with gettext checks and match
exclusions without case sensitivity. Existing engine and voice configuration
code is outside this maintenance change.

## Automation and runtime checks

GitHub Actions checks each pushed branch or pull request, builds that variant,
runs its existing tests when present and uploads review artifacts for 14 days.
It does not publish releases or update an add-on store. Its permissions are
read-only. No network download of a license or engine is performed by SCons.

Build checks do not run NVDA, COM or synthesis DLLs. Verify the resulting package
on Windows using the branch's intended architecture. Check voice selection,
license import using your existing valid license, language switching and restart.
For brokered audio, retain the documented experimental status and known issues.
